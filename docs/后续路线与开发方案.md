## 一、定位：从「信息面板」升级为「交易纪律闭环」

### 1.1 评审标准对照

大赛要求：来源于真实工作场景、能实际操作、有清晰的输入→处理→输出、能反复使用持续优化、真正提升效率；不做静态页面和概念展示。

| 评审点 | 改版前 | 本轮之后 |
| --- | --- | --- |
| 真实场景 | 短线情绪、异动、交割单复盘，场景真实 | 不变，并补上短线交易者每天都做的「写计划」 |
| 可操作 | 主要是看；能改映射规则、阈值、上传交割单 | 盘前写计划 → 盘中自动盯计划 → 盘后自动对照执行 → 一键把次日清单转成明日计划，每一步都要用户动手且有结果反馈 |
| 输入→处理→输出 | 输入只有交割单 | 输入：计划（标的/区间/止损/仓位/纪律）、交割单、心得；处理：区间与止损监控、计划内外对照、7 类偏差识别；输出：执行率、纪律曲线、次日清单、Markdown 复盘日志 |
| 反复使用、持续优化 | 只把一条复盘结论写回状态栏 | 计划按日期长期保存；纪律曲线按交易日展示偏差次数是否在下降；复盘弱点自动写入次日计划的「今日纪律」 |
| 差异化 | 情绪温度计、异动归因在同类作品里常见 | **「计划执行率」「计划外交易亏了多少」**是同类作品少见的量化角度，直接回答「我是不是知行合一」 |

### 1.2 一句话卖点

> 不只告诉你市场怎么样，还告诉你**你有没有按自己的计划做**：盘前写下计划，盘中盯着计划，收盘算出「计划外交易亏了多少」，再把教训写进明天的计划。

### 1.3 参赛建议

- **赛道**：主投「综合工具工作台」（覆盖盘前、盘中、盘后全流程）。规则允许一人多投，可再拆一个「盘后工作台」版本，只保留复盘、计划执行对照、纪律曲线、次日清单和复盘日志，主打「一键完成复盘总结和次日关注清单」，正好对上赛事文案。
- **名称示例**：《短线交易闭环作战台：计划—盯盘—复盘—改进》+ 综合工具赛道。
- **演示路径（3 分钟内能走完）**：
  1. 打开页面，顶部「闭环进度」4 个步骤全是灰色。
  2. 盘前计划：看情绪阶段给出的仓位上限与主线，添加 2 只标的（区间 + 止损）。仓位超过上限时页面会提示。
  3. 盘中异动：「计划盯盘」表显示距区间、距止损，触发的标的排在异动列表最前。
  4. 盘后复盘：点「载入示例交割单」，看计划执行率、计划外胜率、纪律曲线、7 类偏差。
  5. 次日关注清单：勾选后「加入下一交易日计划」，切回盘前就能看到明天的计划。
  6. 「一键复制复盘日志」，粘贴到社区帖子或发给问财 AI 继续追问。
- **帖子截图建议**：闭环进度条全部点亮；计划执行对照卡片（计划外胜率明显低于计划内）；纪律曲线；次日关注清单。

| 6 | 主线题材追踪 | 情绪温度页签 | 拆分涨停原因，统计当日家数、前一日、近 5 日累计、连续上榜天数、近 10 日热度、龙头和状态（主线延续 / 高位分歧 / 新发酵 / 退潮 / 持续活跃 / 轮动）；状态栏显示当前主线 |

### 修复的问题

| 问题 | 原因 | 修复 |
| --- | --- | --- |
| 「情绪化报复性交易」永远 0 次 | 判定条件 `prev.price < prev.amount / prev.qty` 恒为假，也没有检查 30 分钟 | 配对时记录每笔卖出的已实现盈亏，亏损卖出后 30 分钟内同日买入才计入 |
| 交割单乱序时配对出错 | 按文件顺序配对 | 先按日期和时间排序 |
| 部分成交丢数量 | 卖出只配对一笔买入，剩余数量被丢弃 | 改为先进先出、按剩余数量逐笔配对 |
| 「过早止盈」影响恒为 0 | 只统计亏损的交易 | 影响改为「少赚的部分」（卖出后 5 日最高收盘 − 卖价）× 数量；追高的影响改为「相对收盘多付的成本」 |
| 「亏损后加仓摊平」误报 | 只比较历史买价，不看是否仍有持仓 | 改为仍有持仓且新买价低于上一次买价 |
| 复盘页顶部一直显示「正在读取交割单…」 | 成功后没有更新这段文案 | 改为显示成交笔数、平仓笔数、合计盈亏、胜率与代价最大的偏差 |
| 第一条建议文案固定写「核对买点是否偏离收盘 3%」 | 建议文案与偏差类型无关 | 每类偏差给出对应的改进动作（`BIAS_ADVICE`） |
| 连板梯队最新交易日封单额全是 `--` | 天梯数据不带封单额 | 用当日涨停池的 `seal_money` 补上 |
| 指标格末行空白处露出灰色底 | 用背景色当分隔线 | 改为描边分隔 |
| 窄屏下页签文字被挤成竖排 | 新增进度条后空间不足 | 窄屏时页签换行、进度条独占一行 |

### P0-2 涨停池全量分页

> 状态：代码已完成（2026-10-20，模拟宿主回归通过），以下为客户端验收项。

- **现状**：涨停池每天只取 `size: 60`，并按连板数排序。涨停超过 60 家时，首板只取到一部分，导致主线题材家数偏小、主线首板清单不全。
- **做法**：在 `loadDayEmotion` 里按 `pagination.total` 翻页（每页 60，最多 5 页），合并到 `items`。20 日历史可以只翻最新 5 个交易日，以控制请求量；更早的日期保留 60 条，并在题材卡片里注明样本口径。
- **验收**：
  - [ ] 选一个涨停 ≥ 80 家的交易日，`entry.items.length === pagination.total`（或等于翻页上限，并有注明）。
  - [ ] 主线题材卡片的说明里不再出现「前 60 只」，或者已改为准确描述实际口径。
  - [ ] 首次加载总时间增加不超过 3 秒（在客户端里实测）。

### P0-3 情绪阶段有效性自检（给评委看的「这个模型靠不靠谱」）

> 状态：代码已完成（2026-10-20，模拟宿主回归通过）。实现口径：前两项指标由 60 日情绪窗口直接统计（零额外请求，先渲染 20 日再后台扩窗）；「昨日涨停次日平均涨幅」按最近 20 个样本日、每日前 40 只涨停股用 `prices-historical` 渐进加载，按股票去重合并区间，样本缺失时该列显示 `--`。以下为客户端验收项。

- **目标**：在情绪温度页签新增一张小表：各情绪阶段**次日**的平均涨停家数变化、连板晋级率、昨日涨停次日平均涨幅。用历史数据证明「阶段判定对第二天有区分度」。
- **数据**：前两项只需要已有的逐日涨停池；第三项需要第 T 日涨停股在 T+1 日的涨跌幅，可以用 `prices-historical` 批量取，也可以看能力目录里有没有「昨日涨停表现」类数据。
- **做法**：把历史窗口从 20 日扩到 60 日（分批加载，先渲染 20 日）；按 T 日的阶段分组，统计 T+1 日的指标。
- **验收**：
  - [ ] 表格至少覆盖 4 个阶段，每个阶段的样本天数都显示出来；样本少于 3 天的阶段标注「样本不足」。
  - [ ] 结论句会自动比较「高潮/发酵」与「退潮/冰点」的次日晋级率差值。
  - [ ] 60 日窗口加载完成前，页面其余部分不卡顿（先渲染 20 日结果）。

### P1-3 下单客户端版同步计划与复盘
