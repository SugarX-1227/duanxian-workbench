## 三、数据区域与能力映射（12 个区域）

| 数据区域 | 采用能力 | 关键口径 |
| --- | --- | --- |
| 外部指标 | `market-overview`（usshare/hkshare 热点指数）+ `lumi/native-data-client`（检索 + 行情会话） | 已取得报价的对象才展示；未唯一匹配或不返回报价的对象自动隐藏 |
| 映射结果 | `ths-index-list`（行业/概念目录）+ `index-prices-snapshot` + `ths-index-constituents` + 原生行情 | 强度 = \|外部涨跌幅 × 规则权重\|；代表个股由检索唯一匹配后取行情 |
| 情绪核心指标 | 涨停池 / 跌停池 / 炸板池 + `index-prices-historical`（沪、深成交额合并）+ 原生行情（前一交易日涨停池次日表现） | 炸板率 = 炸板 ÷（涨停 + 炸板）；晋级率 = 今日连板家数 ÷ 昨日涨停家数 |
| 情绪分与阶段 | 上述三类涨跌停池 + 指数日线（逐日重建） | 五分项加权：涨停家数 28%、涨停跌停差 18%、封板质量 18%、连板高度 18%、成交额环比 18%；阶段 = 情绪分 + 炸板率 + 与前一交易日比较 |
| 连板梯队 | `datahub-limit-up-ladder` + 涨停池 | 最新交易日用天梯矩阵与 `window.board_caps`；历史交易日按当日涨停池连板数分层 |
| 监控范围 / 监控行情 | `user-sectors` + 原生行情会话 | 证券名称由行情字段补全；页面只维护本地补充范围，不改写客户端自选 |
| 异动原因 / 资讯 / 资金 | `anomaly-analysis-stock`、`stock-info-events`、`capital-flow`、`datahub-dragon-tiger-list` | 归因优先级：个股消息 > 资金行为 > 板块联动 > 大盘拖累 > 独立异动 |
| 交割单与区间行情 | 用户上传文件解析 + `prices-historical`、`index-prices-historical`、`datahub-trading-calendar` | 归因口径：择时 =（买入日收盘 − 买入价）× 数量；仓位 =（该笔金额 ÷ 平均单笔金额 − 1）× 基准收益额；选股 = 总收益 − 择时 − 仓位 |
| 环境对照统计 | 近 20 交易日三类涨跌停池 + 交易日历 | 按交易日情绪阶段分组统计胜率、盈亏比、平均收益、亏损占比 |

## 五、未验证项与已知限制

1. **真实 Host 未验证（host-pending）**：本环境无 jsdom/浏览器驱动，运行验收为 `not-run`；页面已实现「挂载/用户动作 → 具名请求 → 解析 → DatasetState → UI 消费」的可执行链路，但宿主实际取数结果、字段覆盖率与权限状态待联调确认。
2. **跨市场与期货/外汇行情覆盖率未验证**：恒生指数期货、A50期货、美元兑人民币、10年期美债收益率、原油、黄金、铜依赖宿主对全球标的的检索与实时报价支持；未返回报价时按用户决定隐藏，映射规则仍对已取得对象生效。
3. **历史情绪分项差异**：`昨日涨停今日平均涨幅` 需要前一交易日成分股的当日行情，只在最新交易日可算，因此不参与综合情绪分（避免历史与当日口径不可比），仅作为核心指标单独展示。
4. **交割单为 CSV/TXT 文本解析**：券商 Excel 导出需另存为 CSV；表头按关键词识别，列名差异过大时可能解析为空（此时不生成复盘结果，而非显示占位）。
5. **内置示例交割单**：按用户要求内置，用于无数据时完整体验全部复盘功能，界面明确标注为示例交割单，不作为真实数据源，也不参与任何行情取数。
6. **业务知识核对状态**：`lumi-finance-knowledge` 随包未提供查询脚本（`scripts/pm_wiki.py` 不存在），本页采用公开 A 股通用口径（红涨绿跌、涨停/炸板/连板/晋级率的常见定义）并在页面内显式给出计算口径；术语审计中「晋级率」「炸板率」「情绪阶段」命名标记为 `unverified`，保留当前文案，未强行替换。
7. **本地持久化**：映射规则、异动阈值、本地补充范围、复盘诊断摘要存于本地存储（`scs.*` 键），换设备/清缓存后不保留。

## 六、视觉修复轮次（颜色与可读性）

用户反馈「颜色不对、看不清内容」后定位原因：页面原先用宿主语义变量取文本色，却给自己的卡片写死了浅色底色；当宿主只提供文本类变量、不提供底面类变量（或全局颜色规则后注入）时，出现浅底浅字的低对比，涨跌等带独立色值的元素却正常。

修复内容（仅展示层，数据链路与业务口径未变）：

1. 改为页面自带完整调色板：`:root` 浅色与 `html.theme-dark` 深色两套取值，正文 `#11151b` / 深色 `#eef2f7`，次要与弱化文本分别提升到 `#333c48`/`#59636f`，红色涨、绿色跌在两种主题下都保证可读。
2. 在 `.app` 与状态栏、卡片、指标格、表格、按钮、输入框、标签、异动卡片、偏差行、提示浮层等组件上显式声明文本色与底色，杜绝宿主全局颜色规则注入造成的对比丢失。
3. 新增主题探测与监听：按宿主主题标记、宿主底面/文字变量亮度、系统配色逐级判断，自动切换深/浅调色板，并在宿主主题变化时实时跟随。
4. 阶段色（发酵等）调深，保证状态栏胶囊上的白字可读。

同上：本轮仅静态交付，真实宿主渲染与对比度仍需在客户端内确认。

### 未验证项

1. **页面渲染与客户端内取数结果未验证**：注册状态为 installed、入口文件与根路径已核对一致，命令通道已逐条实测，但页面自身在客户端 CEF 内的运行结果需要打开页面确认。
